# AGENTS.md — Start here

This repo is **BasaManager** (বাসা ম্যানেজার), a multi-tenant apartment management web app (PWA)
for Bangladeshi landlords, their caretakers and their tenants.
Landlords run buildings, units and leases. Every month the app builds each tenant's bill (rent + fixed
charges + metered electricity, prorated, with late fees), collects payments online through SSLCommerz
(sandbox) or by confirmed cash/bKash claims, issues PDF receipts, tracks maintenance requests live,
posts building notices, stores tenant documents privately, and reports what was billed, collected and
still due.

**Planned** with the owner (Rony). **Designed, built, tested, deployed and documented** by a team of
Antigravity and Claude agents, end to end, with no human in the loop after planning. The owner reviews the
finished product and must be able to **explain every feature**, so the learning docs
(`.agent/10-LEARNING.md`) are a deliverable with the same weight as the code.

## Key decisions (already made — do not re-open)

| Topic            | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Users & roles    | Admin (platform), Landlord (owns one organisation), Caretaker (staff, per assigned building), Tenant (own lease only). Membership and role are per organisation; one email can hold several.                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Tenancy model    | One shared Postgres schema with `org_id` on every organisation-owned row, enforced **twice**: in the service layer and by Postgres **row-level security** (the API connects as a non-owner role and sets `app.org_id` / `app.user_id` per transaction).                                                                                                                                                                                                                                                                                                                                                                          |
| Device           | Installable PWA. Landlord/caretaker screens desktop-first, tenant screens mobile-first. Design and test sizes: **1440×900** and **390×844**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Language         | English UI, all strings through i18n (`react-i18next`), ready for Bangla later. Currency BDT (৳), timezone **Asia/Dhaka**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Stack            | TypeScript strict everywhere. **pnpm monorepo**: `apps/web` (React + Vite + React Router + TanStack Query + Tailwind v4 + shadcn/ui), `apps/api` (Node 22 LTS + Express 5 + Prisma + Zod + Pino), `apps/worker` (cron, outbox delivery, PDFs), `apps/docs` (VitePress), `packages/shared` (Zod schemas + types shared by web and api), `packages/domain` (pure billing logic).                                                                                                                                                                                                                                                   |
| Database         | **PostgreSQL 17**, self-hosted in Docker. Separate databases per environment: `dev` (local container), `test` (fresh per CI run / local test container, wiped between suites), `staging` and `prod` (on the VPS, separate users and passwords). Prisma migrations are the only way schema changes; RLS policies live in SQL migrations.                                                                                                                                                                                                                                                                                          |
| Auth             | Built in-house on proven primitives so every step is explainable: **argon2id** passwords, **JWT access token (15 min)** + **opaque rotating refresh token (30 days, hashed in DB, reuse detection kills the family)**, both in `httpOnly` `Secure` `SameSite=Lax` cookies, CSRF header check on unsafe methods, **Google OAuth** via `arctic` (PKCE + state), email verification, invite tokens, password reset, rate limiting + lockout.                                                                                                                                                                                        |
| Real-time        | Socket.io with the Redis adapter. Handshake authenticated from the access cookie. Rooms per user, org, building and maintenance request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Jobs             | `apps/worker` runs `node-cron` schedules guarded by a Redis lock **and** DB unique constraints (idempotent). Notifications use a Postgres **outbox** table written in the same transaction as the event; the worker delivers with retries and backoff.                                                                                                                                                                                                                                                                                                                                                                           |
| Payments         | **SSLCommerz sandbox** (init → redirect → IPN → validation API; the redirect never changes money). Manual payments via staff entry or tenant claim + staff confirmation. All money as integer poisha.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Email            | Nodemailer over **Resend SMTP** (free tier), sending from `notify.basamanager.rhrony05.me`. React Email templates. **Mailpit** container in dev/test; tests never send real email.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Push             | **Standard Web Push** (VAPID keys generated by the agents, `web-push` library on the server, service worker in the PWA). No Firebase. Push service mocked in tests.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Files            | **Cloudinary** (free plan) behind a small `storage` interface. Every file is uploaded as `type: authenticated` (never public) under `basamanager/<env>/org/<orgId>/…`; images re-encoded with `sharp` (EXIF stripped, max 2000 px) plus a 400 px thumbnail; PDFs as `resource_type: raw`. Access only through **expiring signed download URLs** (`private_download_url`, 5 min) after a permission check. Dev/test use the `local` driver (disk + HMAC-signed expiring URLs), so tests never call Cloudinary.                                                                                                                    |
| PDF              | Puppeteer in the worker, rendering HTML templates (receipts, statements, settlements).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Maps             | Leaflet + OpenStreetMap tiles (no API key).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Observability    | Pino JSON logs with request IDs; **Sentry** for web, api and worker (errors + performance, release tagged with the git SHA); a `/health` and `/ready` endpoint; free uptime monitor on prod.                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Hosting          | **Azure for Students** VM (Standard B2s, 2 vCPU / 4 GB, Ubuntu 24.04 LTS), created by the DevOps agent with `az` CLI. Docker Compose; **Caddy** reverse proxy with automatic TLS. Staging and prod are separate compose projects on the same VM. DNS on **Cloudflare**: `basamanager.rhrony05.me` (prod), `staging.basamanager.rhrony05.me`, `docs.basamanager.rhrony05.me`. The owner keeps the VM for **about one month** (a test run, roughly $30 of the $100 credit). Everything needed to rebuild it lives in the repo (`infra/` scripts + `operations/` runbooks), so the stack can be re-created on any Ubuntu VPS later. |
| Backups          | Nightly `pg_dump` of staging + prod to **Azure Blob Storage** (storage account in `rg-basamanager`, private container `backups`, container-scoped SAS token, lifecycle rule deletes blobs older than 30 days). Paid from the student credit (cents), deleted with the resource group. A restore drill runs in CI weekly against a throwaway container.                                                                                                                                                                                                                                                                           |
| CI/CD            | GitHub Actions. **PR**: lint, typecheck, unit, integration (Postgres + Redis + Mailpit service containers, local storage driver), e2e (Playwright, desktop + mobile), docs build, `pnpm audit`, gitleaks, CodeQL. **Merge to `main`**: build images → GHCR → deploy to staging over SSH → run migrations → smoke tests. **Tag `v*`** (made by the lead agent after staging is green) → deploy prod the same way; automatic rollback to the previous image if smoke tests fail.                                                                                                                                                   |
| Repo             | Private GitHub repo `RHRONY05/BasaManager`. Short-lived feature branches, Conventional Commits, squash merge. Branch protection on `main`: CI green + reviewer-agent approval. Never commit secrets.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Testing          | 4+ layers: unit (Vitest), integration (Vitest + Supertest against a real Postgres), e2e (Playwright, desktop + mobile projects, axe), load smoke (k6), Lighthouse on mobile + desktop with targets in `09-TESTING.md`. Seeded test users per role; every external service mocked or sandboxed.                                                                                                                                                                                                                                                                                                                                   |
| Design           | Done **autonomously** by the designer agent in task V2 (no human approval gate), using the `ui-ux-pro-max`, `frontend-design` and `design-canvas` skills with their self-critique loops. Wherever those skills would ask the user, the designer decides and records why in `design/README.md`. After V2, other agents implement the design exactly and make no design decisions. Tokens only, no raw colours.                                                                                                                                                                                                                    |
| UI quality       | Two mandatory project skills: `.claude/skills/mobile-layout-qa` (no overflowing text, no wrapped labels, checked by an automated geometry audit at 320–768 with stress content) and `.claude/skills/ui-states` (instant navigation feedback, skeletons, preloading, cache rules, proved by a slow-network e2e spec).                                                                                                                                                                                                                                                                                                             |
| Learning docs    | Per `10-LEARNING.md`: every feature and concept documented with level 0/1/2 diagrams (SVG in the owner's `visual-diagram` style, Mermaid for sequence/state), code walks, data map, data lifecycle, edge cases, self-check. Published as a VitePress site. Written in the same task as the code.                                                                                                                                                                                                                                                                                                                                 |
| Agent team       | **Antigravity (Gemini 3.8 Flash High) is the lead and builder, one session per goal, started by the owner with `/goal` (`.agent/GOAL.md`).** It calls Claude through the `claude` command for critical tests first, every PR review, one bug hunt per goal, hard debugging and DevOps (owner decision 2026-11-09). Details in `11-AGENT-TEAM.md`.                                                                                                                                                                                                                          |
| Docs follow code | The `.agent/` pack and `docs/` always describe the app as it is. Any change updates the owning doc in the same commit. `/sync-docs` audits and repairs drift.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Cost             | Free tiers only (Resend, Cloudinary, Sentry, SSLCommerz sandbox, GitHub, Cloudflare DNS, uptime monitor). The Azure VM runs on student credit. Anything that would cost money → stop and add a Human step.                                                                                                                                                                                                                                                                                                                                                                                                                       |
