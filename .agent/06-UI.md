# 06 — UI behaviour

This doc owns **behaviour**: which pages exist, what's on them, what each control does, and the
states. **Looks** belong to `design/` (created by the designer agent in V2). Where they disagree on
behaviour, this doc wins; on looks, `design/` wins.

## Global
- Sizes: desktop **1440×900**, mobile **390×844**. Breakpoint `md` = 768 px.
- **Landlord/caretaker/admin shell:** left sidebar (collapsible) on desktop; on mobile a top bar + bottom tab
  bar with ≤ 5 items + "More" sheet. **Tenant shell:** mobile-first, bottom tab bar (Home, Bills, Requests,
  Notices, Account); on desktop the same content in a centred column ≤ 720 px with a top nav.
- Top bar: org switcher (if > 1 membership), notification bell with unread count (live), account menu.
- Money: `৳12,500` (en-IN grouping is fine for v1: `৳1,25,000` — use `Intl.NumberFormat('en-IN')`). Dates:
  `10 Nov 2026`. Months: `November 2026`. All times shown in Asia/Dhaka.
- **Loading & navigation** follow `.claude/skills/ui-states/SKILL.md` (mandatory): a click changes the URL, the
  active nav item and shows the destination's layout-matched skeleton within 100 ms; no awaited data in route
  loaders; links preload on hover/focus/touch; cached pages are instant; filters keep old results visible while
  loading; a 2 px top progress bar for waits over 150 ms.
- **Mobile layout** follows `.claude/skills/mobile-layout-qa/SKILL.md` (mandatory): checked at 320/360/390/414/768
  with stress content and the `en-XA` pseudo-locale; labels never wrap, text never leaves its box, no horizontal scroll.
- Every list/data region: layout-matched skeleton, empty state with one primary action, error state with Retry, cursor "Load more".
- Every mutation: button shows loading and is disabled; success toast; error toast/inline with the API
  `message`. Destructive actions use a confirm dialog that names the thing ("Void payment of ৳5,000 from Karim?").
  Actions that need a reason (void, reject, waive, adjustment) have a required reason field.
- Forms: labels always visible, inline errors under the field from the shared Zod schema, submit on Enter.
- Status badges (one component, consistent everywhere): bill `draft/issued/partially paid/paid/void/overdue`,
  payment `pending/confirmed/rejected/void`, request `open/assigned/in progress/resolved/closed`, lease `pending/active/notice/ended`.
- Real-time: when a socket event arrives for something on screen, the related query is refetched; a subtle
  highlight shows what changed. Connection lost → small "Reconnecting…" pill; no blocking.
- PWA: installable (manifest, icons from design), offline → app shell + "You're offline" banner; no offline writes.
- Push opt-in: never on first visit. Shown as a card on the tenant home and in Account → Notifications
  after the first bill is issued; explains what they'll get. On iOS Safari not installed: show "Add to Home
  Screen to get notifications" instructions instead.
- Keyboard: `/` focuses search on list pages, `g d` dashboard, `g b` bills, `g m` maintenance (staff only);
  `?` opens the shortcut sheet. Focus visible everywhere, Escape closes dialogs/sheets.
- Suspended org → full-page "This account is suspended" with sign-out and org switcher only.

## Public & auth pages
| Route | Content & behaviour |
|---|---|
| `/` | Landing (redesigned 2026-11-10; looks: `design/README.md` "Landing + auth pages"). Hero: headline, lead, "Create landlord account", "Sign in", and an **interactive building cut-away**: 10 sample flats with status (Paid / Due / Repair / Vacant); tapping a flat (a real `button`, `aria-pressed`) shows that flat's sample bill (`aria-live=polite`), 4A selected first. Then: four worked examples (bills, payments, repairs, notices) beside a sticky intro + "Also included" (documents, reports); who it's for (landlords, caretakers, tenants); how it works (3 steps); call to action. Header anchors to #features, #roles, #how. All sample data is static in the page; nothing is fetched. Signed-in users are redirected to their home |
| `/signup` | Full name, email, password (strength hint), organisation name, Google button. Success → "Check your email" screen with Resend (60 s cooldown) |
| `/login` | Email, password, "Forgot password?", Google button. Errors: generic invalid credentials; locked → shows minutes left |
| Auth layout (all auth routes) | ≥ 768 px: left inset panel (sky, brand, headline, sample bill; the building drawing from 1024 px) + form on the right. < 768 px: brand bar + form only |
| `/verify-email?token=` | Verifying… → success (continue) / invalid link (resend if signed in) |
| `/forgot-password`, `/reset-password?token=` | Always the same "If an account exists, we sent a link" message |
| `/invite/:token` | Org name, role, inviter. New user: name + password, or Google. Signed in with another email → explains the mismatch, offers sign out |
| `/pay/result?tran=` | "Checking payment…" spinner polling the intent → Paid (receipt link) / Failed / Cancelled / "Still processing, we'll notify you" |

## Landlord
| Route | Content & behaviour |
|---|---|
| `/l` Dashboard | Month picker. KPI cards: billed, collected, outstanding (with overdue count), occupancy %. Chart: last 6 months billed vs collected. Lists: drafts waiting (button "Review drafts"), pending payment claims, urgent/old requests. First-run (no buildings): onboarding checklist (add building → add units → add tenant → set billing) |
| `/l/buildings` | Cards per building: address, units, occupancy, outstanding. "Add building" |
| `/l/buildings/:id` | Tabs: **Units** (table: label, floor, type, tenant, rent, status, dues; row → unit drawer), **Billing settings** (bill/due day, grace, late fee type/value, electricity rate; preview text "Bills are created on the 1st and due by the 10th"), **Notices**, **Map** (Leaflet pin, draggable in edit mode) |
| unit drawer | Unit details + charges editor, current lease summary, "Add tenant" (if vacant), archive |
| `/l/tenants` | All leases, filter by building/status, search by name/unit. Row → lease |
| `/l/leases/new?unitId=` | Stepper: tenant (email, name) → terms (start date, rent, deposit, household, charges, move-in reading if submeter) → review (shows the first bill preview incl. proration) → sends invite |
| `/l/leases/:id` | Header: tenant(s), unit, status. Tabs: **Overview** (deposit held, credit, dues, record deposit), **Bills**, **Payments** (Record payment), **Documents** (upload/view/delete), **Requests**, **History**. | `/l/bills/:id` | Line items with explanations, adjustments (add with reason), late fee (waive with reason), allocations, payments, status timeline. Issue / Void buttons by status |
| `/l/payments` | Tabs: **Pending claims** (proof thumbnail, TrxID, Confirm / Reject with reason), **All payments** (filters, void), Record payment dialog (lease search, amount, method, reference, date) |
| `/l/maintenance` | Board view (columns by status) on desktop, list on mobile; filters building/priority/assignee; card shows age. Detail drawer: timeline, photos, assign, status buttons valid for the current state, comment box |
| `/l/notices` | List + composer (building, title, body, pin, expiry) |
| `/l/team` | Caretakers: invite (email + buildings), edit buildings, remove; open invites with revoke/resend |
| `/l/reports` | Monthly statement per building (generate → download when ready), lease statement range picker |
| `/l/settings` | Organisation name; link to Account |

## Caretaker
Same shell; nav: **Today**, Billing (Readings + Drafts read-only), Payments, Maintenance, Notices.
`/c` Today = readings missing this month (count + link), pending claims, my assigned requests by priority.
Pages reuse the landlord components with role-limited actions (no issue/void/waive/adjust, no
documents, no team, no settings). Buttons that aren't allowed are **not shown** (not disabled).
