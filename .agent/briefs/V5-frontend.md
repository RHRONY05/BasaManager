## Scope (only `apps/web/**`)
1. **API client** (`src/lib/api/client.ts`): send `credentials: 'same-origin'`; on unsafe methods add `X-CSRF-Token` read from the `bm_csrf` cookie; add `X-Org-Id` from the active org when set; on `401 UNAUTHENTICATED` run **one** single-flight `POST /api/auth/refresh` (shared promise), then retry the original request once; if refresh fails (`SESSION_REVOKED` or other) clear the session and navigate to `/login`. Never refresh on any other code. Unit tests for: single-flight with 3 parallel 401s, no refresh on `INVALID_CREDENTIALS`, retry once only.
2. **AuthProvider** (`src/app/auth/`): `useAuth()` returns `{status: 'loading'|'signedOut'|'signedIn', user, memberships, activeOrg, role, switchOrg(orgId), signOut()}`. Loads `GET /api/me` through TanStack Query (key in `lib/api/keys.ts`); active org persisted in `localStorage` (`bm.activeOrg`), default = first active membership; `signOut` calls `/api/auth/logout`, clears the query cache, goes to `/login`. Listens to the `session:revoked` socket event only if a socket client already exists (no socket wiring in this part).
3. **Route guards**: `RequireAuth` (signedOut → `/login?next=<path>`), `RequireRole(roles)`, and `homeFor(role)` (`landlord→/l`, `caretaker→/c`, `tenant→/t`, `admin→/a`). Wrap the existing `/l`, `/c`, `/t`, `/a`, `/account` route groups in `router.tsx`. Signed-in users visiting `/`, `/login`, `/signup` are redirected to `homeFor(role)`. Never flash protected content: while `loading` show the route skeleton, not the page.
4. **Pages** (replace the placeholders in `src/pages/auth/`, add new routes + `pageLoaders` entries in `lib/router/preload.ts`): `LandingPage` (`/`), `LoginPage`, `SignupPage` (with the "Check your email" screen and a 60 s resend cooldown), `VerifyEmailPage` (`/verify-email?token=`), `ForgotPasswordPage`, `ResetPasswordPage` (`/reset-password?token=`), `InvitePage` (`/invite/:token`: preview, new-user name+password form or Google button, signed-in-with-another-email mismatch card with sign-out). Behaviour exactly as in 06-UI. Login shows minutes left on `ACCOUNT_LOCKED` (read from the error details/message the API returns; check `apps/api/test/auth/lockout.int.test.ts`), a generic message for `INVALID_CREDENTIALS`, and a `RATE_LIMITED` message. A `?error=google_failed` query shows a banner. The Google button is a plain link to `/api/auth/google/start` (with `?invite=<token>` on the invite page). Password field: show/hide toggle, strength hint (min 10 chars; use the shared schema for validation), `react-hook-form` + `zodResolver` with the schemas from `@bm/shared`. `next` redirect after login must only accept same-origin paths starting with a single `/`.
5. **i18n**: every string in `src/locales/en/common.json` under `auth.*`; no literals in JSX. **Design**: tokens only (no raw colours, run the token lint), layouts match the design artboards at 1440 and 390; labels never wrap (`mobile-layout-qa`); buttons show a pending state and are disabled while submitting; each page has a skeleton/loading state via `ui-states` rules; inline field errors have `aria-describedby`; focus moves to the first error.
6. **Tests** (Vitest + Testing Library, in `src/**/*.test.tsx`): client refresh behaviour (above), `RequireAuth`/redirect logic, `next` sanitiser, login error mapping, signup cooldown (fake timers). No Playwright in this part (a later part writes `auth.spec.ts`).
